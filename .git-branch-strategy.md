# Git Branch Strategy (Google Style)

## 🌳 Branch Structure

### **Main Branches**
- **`main`**: Production-ready code
- **`develop`**: Integration branch for features

### **Supporting Branches**
- **`feature/*`**: New features
- **`release/*`**: Release preparation
- **`hotfix/*`**: Critical production fixes

## 📋 Naming Conventions

### **Feature Branches**
```
feature/blog-system          # Blog functionality
feature/user-authentication  # User auth system
feature/comment-system       # Comment functionality
feature/search-optimization  # Search improvements
```

### **Release Branches**
```
release/v1.2.0              # Version 1.2.0 preparation
release/blog-launch         # Blog system launch
```

### **Hotfix Branches**
```
hotfix/critical-security-fix
hotfix/urgent-bug-fix
```

## 🔄 Workflow

### **1. Feature Development**
```bash
# Start from develop
git checkout develop
git pull origin develop

# Create feature branch
git checkout -b feature/blog-system

# Work on feature...
git add .
git commit -m "feat: Add blog post creation form"

# Push feature branch
git push origin feature/blog-system

# Create Pull Request: feature/blog-system → develop
```

### **2. Release Process**
```bash
# Create release branch from develop
git checkout develop
git checkout -b release/v1.2.0

# Final testing and bug fixes
# Merge to main when ready
git checkout main
git merge release/v1.2.0
git tag v1.2.0
git push origin main --tags

# Merge back to develop
git checkout develop
git merge release/v1.2.0
```

### **3. Hotfix Process**
```bash
# Create hotfix from main
git checkout main
git checkout -b hotfix/critical-fix

# Fix the issue
git add .
git commit -m "fix: Critical security vulnerability"

# Merge to main
git checkout main
git merge hotfix/critical-fix
git tag v1.2.1

# Merge to develop
git checkout develop
git merge hotfix/critical-fix
```

## 📝 Commit Message Convention

### **Format**
```
<type>(<scope>): <description>

<body>

<footer>
```

### **Types**
- **feat**: New feature
- **fix**: Bug fix
- **docs**: Documentation changes
- **style**: Code style changes (formatting, etc.)
- **refactor**: Code refactoring
- **test**: Adding or updating tests
- **chore**: Maintenance tasks

### **Examples**
```
feat(blog): Add blog post creation form
fix(chatbot): Resolve typing indicator animation issue
docs(readme): Update installation instructions
style(ui): Apply consistent rounded corners
refactor(components): Extract reusable card component
test(api): Add unit tests for blog endpoints
chore(deps): Update dependencies to latest versions
```

## 🔍 Branch Protection Rules

### **main branch**
- Require pull request reviews
- Require status checks to pass
- Require branches to be up to date
- Restrict pushes to main

### **develop branch**
- Require pull request reviews
- Require status checks to pass
- Allow force pushes (for rebasing)
